Глава 1. Знакомство с React

📜 Что такое React

React — это JavaScript-библиотека для создания пользовательских интерфейсов (UI), разработанная компанией Meta (Facebook). Основная идея React заключается в том, чтобы разбивать интерфейс приложения на небольшие независимые компоненты, которые можно многократно использовать и комбинировать между собой.

💡 Определение

React — декларативная компонентная библиотека для разработки современных пользовательских интерфейсов.

До появления React разработка сложных веб-интерфейсов сопровождалась большим количеством прямых операций с DOM: созданием элементов, поиском узлов, изменением атрибутов и обновлением содержимого страницы. По мере роста проекта такой подход становился всё сложнее, а вероятность появления ошибок возрастала.

✅ Главная идея React

Вместо пошагового изменения элементов страницы разработчик описывает конечный результат. React сам вычисляет минимальный набор изменений, необходимых для обновления интерфейса.

Компонентный подход

📜 История появления React

Сегодня React является одной из самых популярных библиотек для создания пользовательских интерфейсов. Однако его появление стало ответом на вполне конкретные проблемы, с которыми столкнулись разработчики Facebook при развитии собственных веб-приложений.

💡 Почему появился React?

React был создан инженером Facebook Джорданом Уолком (Jordan Walke) для упрощения разработки сложных пользовательских интерфейсов, которые постоянно изменяются в ответ на действия пользователя.

До появления React

В конце 2000-х годов большинство веб-приложений строилось на основе непосредственного изменения DOM. Разработчики самостоятельно искали элементы, изменяли их содержимое, добавляли обработчики событий и синхронизировали состояние интерфейса с данными приложения.

Ключевые этапы развития

Версия Основные изменения
0.x Первые внутренние версии Facebook.
15 Последняя версия классической архитектуры React.
16 Новая архитектура Fiber, Fragments, Portals, Error Boundaries.
16.8 Появление Hooks.
17 Подготовка к постепенному обновлению приложений.
18 Concurrent Rendering, Automatic Batching, новые API.
19 Actions, улучшенная работа с формами, развитие Server Components.

Почему это важно знать?

✅ Практический совет

Изучая React сегодня, ориентируйтесь на современные возможности библиотеки, однако полезно знать, когда появились Hooks, Fiber, Concurrent Rendering и другие ключевые технологии. Это значительно облегчает поддержку старых проектов.

⚠️ Важно

В данной книге примеры будут основаны на актуальной стабильной версии React. Особенности устаревших версий рассматриваются только там, где это необходимо для понимания современного подхода к разработке.

Краткие выводы

  • ✅ React развивается эволюционно, сохраняя обратную совместимость.
  • ✅ Наиболее значимыми этапами стали Fiber, Hooks и Concurrent Rendering.
  • ✅ Современная разработка ориентируется на React 19.
  • ✅ Знание истории развития React помогает понимать код разных поколений проектов.

📜 Почему появился React

К началу 2010-х годов веб-приложения стали значительно сложнее. Если раньше сайт представлял собой набор отдельных страниц, то современные сервисы начали работать как полноценные приложения, в которых интерфейс постоянно изменяется без перезагрузки страницы.

Итоги

  • ✅ Сложность веб-приложений потребовала нового подхода к разработке интерфейсов.
  • ✅ Основной проблемой стало ручное управление большим количеством DOM-элементов.
  • ✅ React автоматизировал обновление пользовательского интерфейса.
  • ✅ Разработчик описывает результат, а не последовательность действий.
  • ✅ Такой подход стал основой современной фронтенд-разработки.

SPA-приложение

  • Отсутствие постоянных перезагрузок страницы.
  • Более плавную навигацию.
  • Поведение, похожее на обычное настольное приложение.

Глава 2. Создание первого React-приложения

📜 Подготовка окружения

Прежде чем приступить к разработке React-приложений, необходимо подготовить рабочее окружение. В отличие от обычного HTML и JavaScript, React-проекты используют современные инструменты сборки, менеджеры пакетов и систему модулей.

💡 Что такое окружение разработки?

Окружение разработки — это набор программ и инструментов, необходимых для создания, запуска, тестирования и сборки React-приложений.

Что потребуется

Инструмент Назначение Обязательно
Node.js Среда выполнения JavaScript и менеджер пакетов npm. ✅ Да
VS Code Редактор исходного кода. ✅ Рекомендуется
Современный браузер Запуск и отладка приложения. ✅ Да
Git Контроль версий проекта. ⚠️ Желательно

Почему нельзя просто открыть HTML-файл?

В обычных HTML-проектах достаточно открыть файл index.html в браузере. React работает иначе: проект состоит из множества JavaScript-модулей, которые необходимо объединить и подготовить перед запуском.

⚠️ Важно

React не запускается простым открытием файла index.html. Для разработки используется локальный сервер, который автоматически пересобирает проект при изменении файлов и мгновенно отображает результат в браузере.

Что мы будем использовать

Инструмент Причина выбора
Node.js Стандарт для современной JavaScript-разработки.
npm Устанавливает и обновляет библиотеки проекта.
Vite Быстро создает и запускает React-приложения.
Visual Studio Code Один из самых популярных редакторов для React-разработки.
🔹 На практике

Практически все современные React-проекты используют Node.js, npm (или альтернативные менеджеры пакетов) и один из современных инструментов сборки, например Vite. Освоив этот набор один раз, вы сможете работать с большинством React-проектов без дополнительной настройки.

📝 Что запомнить

  • ✅ Для разработки React требуется подготовленное рабочее окружение.
  • ✅ Основные инструменты — Node.js, npm, Vite и VS Code.
  • ✅ React-проекты запускаются через локальный сервер разработки.
  • ✅ В следующих разделах мы установим и настроим все необходимые инструменты.

📜 Node.js и npm

React-приложения разрабатываются с использованием Node.js — среды выполнения JavaScript. Вместе с Node.js автоматически устанавливается npm (Node Package Manager) — менеджер пакетов, который используется для установки библиотек и управления зависимостями проекта.

💡 Важно понимать

Node.js не нужен для выполнения React-приложения в браузере. Он используется во время разработки: для установки зависимостей, запуска локального сервера и сборки проекта.

Что такое Node.js?

Node.js — это среда выполнения JavaScript вне браузера, построенная на движке Google V8. Она позволяет запускать JavaScript-программы непосредственно в операционной системе и служит основой большинства современных инструментов Frontend-разработки.

Что такое npm?

npm (Node Package Manager) — стандартный менеджер пакетов Node.js. Он позволяет устанавливать библиотеки, обновлять их, удалять и управлять зависимостями проекта.

Инструмент Назначение
Node.js Среда выполнения JavaScript.
npm Менеджер пакетов и зависимостей.
npx Запуск пакетов без глобальной установки.

Как они работают вместе

                React-проект

                    │
                    ▼

                Node.js

                    │
                    ▼

                npm

                    │
                    ▼

                React • Vite • React Router • Axios • ...

Когда выполняется команда установки библиотеки, npm загружает пакет из официального репозитория и сохраняет его в папке node_modules, а также записывает информацию о зависимости в файл package.json.

Основные команды

Команда Назначение
node -v Показать версию Node.js.
npm -v Показать версию npm.
npm install Установить зависимости проекта.
npm run dev Запустить локальный сервер разработки.
npm run build Собрать production-версию приложения.
✅ На практике

Большинство React-разработчиков ежедневно используют всего несколько команд: npm install, npm run dev и npm run build. Остальные команды применяются значительно реже.

❌ Частая ошибка новичков

Не редактируйте папку node_modules вручную. Она создается автоматически и может быть полностью пересоздана командой npm install.

📝 Что запомнить

  • ✅ Node.js — среда выполнения JavaScript, используемая во время разработки.
  • ✅ npm устанавливается вместе с Node.js и управляет зависимостями проекта.
  • ✅ Все установленные библиотеки находятся в папке node_modules.
  • ✅ Информация о зависимостях хранится в файле package.json.
  • ✅ Для повседневной работы достаточно знать несколько основных команд npm.
